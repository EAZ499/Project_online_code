**Основной цикл боя найден. Он распределён по нескольким `.rpy`-файлам, а не собран в одном месте.** Центральная точка входа — `label fightbegin12`, а граница раундов — `label afterenemyattack`.

Ниже — фактическая логика кода, включая места, где она расходится с комментариями. Файлы не менял; анализ статический, без запуска игры.

## 1. Где начинается бой

### Вход из RPG

В `game/4_RPG_КОМНАТЫ.rpy:594–601` взаимодействие с противником запускает бой:

- `dummy_fight` устанавливает `battlenumber = 11`;
- `dummy2_fight` устанавливает `battlenumber = 13`;
- скрывается `game_screen`;
- выполняется `Jump("fightbegin12")`.

`battlenumber` определяет состав врагов и вариант атак.

**Состав противников задаётся в `get_active_enemies()`**, файл `game/1_ВЫБОР_ЦЕЛИ.rpy:74`:

| `battlenumber` | Враги |
|---|---|
| 1 | Арчи |
| 2 | Тревор |
| 3 | ДжевилV1 |
| 4 | Психолог |
| 5 | Спамтон |
| 10 | Арчи, Тревор, ДжевилV1, Психолог |
| 11 | dummy, Тревор, ДжевилV1 |
| 13 | dummy2, Тревор |

То есть бой с манекеном фактически может включать дополнительных врагов.

### Другой вход

В `game/script2.rpy:520` находится `label fightstarts`, который вызывает:

```renpy
call screen fightbegin
```

Экран `fightbegin` через 0,8 секунды переводит в `fightbegin12`.

Оба объекта находятся в `game/1_ВРАГ_ДИАЛОГИ.rpy:51–54`.

### Инициализация боя

**`label fightbegin12` — `game/1_ВРАГ_ДИАЛОГИ.rpy:54`.**

Он:

1. Скрывает RPG-экран.
2. Сбрасывает атакующего, цели и действие.
3. Возвращает персонажей в исходную позицию.
4. Включает `check_enemy_status` — постоянную проверку победы и поражения.
5. Устанавливает `current_round = 0`.
6. Сбрасывает перезарядки и одноразовые способности.
7. Показывает спрайты участников и статус команды.
8. Вызывает вступление `first_turn_dialogue`.
9. Переходит в `enemy_turn`.

**Важно: первым ходит противник. Игрок получает управление только после стартовой вражеской фазы.**

## 2. Общая схема цикла

```text
fightbegin12
    current_round = 0
    ↓
first_turn_dialogue
    ↓
enemy_turn → enemyattack
    стартовая атака врагов: раунд 0
    ↓
afterenemyattack
    current_round: 0 → 1
    ↓
choose_attacker_screen
    выбор героя
    ↓
playerturn2 → buttoms
    выбор команды, умения и цели
    ↓
Heroperformsturn → Heroattacks
    выполнение действия
    ↓
лейбл конкретного действия
    ↓
choose_attacker_screen
    ├─ есть доступные герои → следующий ход героя
    └─ доступных героев нет
         ↓
       enemyattacklabel
         эффекты, регенерация, подготовка арены
         ↓
       enemy_turn → enemydialogue → enemyattack
         ↓
       afterenemyattack
         current_round: N → N + 1
         ↓
       выбор героев следующего раунда
```

Проверка окончания боя работает параллельно этой схеме и может прервать её.

## 3. Какие лейблы и экраны за что отвечают

### Выбор героя

**Экран `choose_attacker_screen`**  
`game/1_ВЫБОР ПЕРСОВ.rpy:233`

Герой доступен, если одновременно:

```python
picked == 1
current_hp > 0
turn == 1
prone_debuff == 0
```

Проверки находятся на строках `257–265`.

Выбор устанавливает `current_attacker` и переводит в `playerturn2`. Для Криса сначала вызывается `Kris_check_control` — проверка подчинения игроку.

**Значения `turn` у героев:**

- `1` — может действовать;
- `0` — ход недоступен/израсходован.

### Меню хода

Лейблы в `game/1_ВРАГ_ДИАЛОГИ.rpy`:

| Лейбл | Назначение |
|---|---|
| `playerturn`, строка 150 | Переход к выбору героя через `character_to_choose` |
| `character_to_choose`, строка 180 | Показывает боевые панели и вызывает выбор героя |
| `playerturn2`, строка 156 | Подготавливает ход уже выбранного героя и переходит в `buttoms` |
| `turn_is_done`, строка 199 | Ставит выбранному герою `turn = 0` и возвращает в `playerturn` |

**`buttoms`** — `game/5_ИНТЕРФЕЙС_БОЯ.rpy:1107`: сбрасывает старое состояние меню и показывает четыре группы кнопок.

Меню выбора находятся в `game/5_ИНТЕРФЕЙС_БОЯ_МЕНЮ.rpy`:

| Экран | Назначение |
|---|---|
| `choose_attack_screen`, строка 898 | Выбор атаки |
| `choose_magic_screen`, строка 911 | Выбор магии |
| `itemchoice2`, строка 1403 | Выбор предмета |
| `actchoice1`, строка 1543 | Выбор действия |

### Выбор цели и исполнение

**`turntarget`** — `game/1_ВЫБОР_ЦЕЛИ.rpy:889`.

Проверяет возможность оплатить умение. Когда выбраны `target` и `attackindex`, для поддерживаемых типов цели через 0,3 секунды запускает `Heroperformsturn`.

**`Heroperformsturn`** — `game/1_ПЕРС_АТАКИ_2.rpy:110`.

- Оплачивает стоимость способности.
- При нехватке ресурсов возвращает в `playerturn2`.
- Скрывает меню.
- Вызывает экран `Heroattacks`.

**`Heroattacks`** — `game/1_ПЕРС_АТАКИ.rpy:224`.

Это диспетчер выполнения: запускает мини-игру атаки, магию, защиту либо переводит в обработку предмета/социального действия.

Далее работают специализированные лейблы:

- атаки и магия: `game/1_ПЕРС_АТАКИ_ЛЕЙБЛЫ.rpy`;
- действия: `game/1_ПЕРС_ДЕЙСТВИЯ.rpy`, завершение — `finish_act:1445`;
- предметы: `game/1_ПЕРС_ИНВЕНТАРЬ_ХОД.rpy`, `perform_item:28`.

После исполнения обычно снова вызывается `choose_attacker_screen`.

## 4. Когда раунд начинается и заканчивается

### Начало раунда

Отдельного универсального `label round_start` нет.

**Фактически следующий раунд начинается в `afterenemyattack`, когда увеличивается `current_round` и игроку открывается выбор героев.**

Файл: `game/1_АТАКИ_ВРАГОВ.rpy:413`.

Таким образом:

```text
Раунд 0: только стартовая вражеская фаза.

Раунд 1: действия героев → вражеская фаза → счётчик становится 2.

Раунд 2: действия героев → вражеская фаза → счётчик становится 3.
```

### Конец фазы героев

В `choose_attacker_screen` считается `available_chars`.

Если `available_chars == 0`, запускается отсчёт, затем через 2,2 секунды переход в `enemyattacklabel`.

Файл: `game/1_ВЫБОР ПЕРСОВ.rpy:2810–2826`.

**Это ещё не конец полного раунда — только конец возможности героев действовать.**

### Подготовка вражеской фазы

**`enemyattacklabel`** — `game/1_ВЫБОР ПЕРСОВ.rpy:2865`.

Выполняет:

- сброс текущего атакующего;
- `reset_heroes_feedness_step()`;
- `apply_debuffs_at_round_end()`;
- `apply_debuffs_at_round_end_enemies()`;
- показ результатов эффектов;
- HP/MP-регенерацию при её наличии;
- появление арены;
- переход в `enemy_turn`.

Кровотечение и обработка `prone` происходят здесь, **перед атаками врагов**, несмотря на название функций `round_end`.

### Когда заканчивается вражеская фаза

**`enemyattack`** — `game/1_АТАКИ_ВРАГОВ.rpy:74`.

Он проверяет `all_battle_enemies_done()`. Для каждого активного врага завершением считается:

```python
враг отсутствует
или dead == True
или current_hp <= 0
или turn == 1
```

Функции находятся на строках `35–41`.

Обрати внимание: **у врагов смысл `turn` противоположен героям**:

- `0` — ещё не завершил атаку;
- `1` — завершил.

Когда все враги завершили фазу, экран делает `Jump("afterenemyattack")`.

### Конец полного раунда

В `afterenemyattack`:

1. Увеличивается `current_round`.
2. Останавливается физика души, освобождается мышь.
3. Активным врагам ставится `turn = 0`.
4. Применяются функции `apply_debuffs_at_round_start*`.
5. При `current_round > 1` перезарядки уменьшаются на один.
6. Сбрасываются позиции героев.
7. Открывается выбор героя следующего раунда.

Стартовая фаза `0 → 1` специально не уменьшает перезарядки в этом лейбле.

## 5. Когда заканчивается весь бой

**`check_enemy_status`** — `game/1_ПОСЛЕ БОЯ.rpy:281`.

Он периодически проверяет:

- если **каждый активный враг мёртв или пощажён** — переход в `after_fight`;
- если **все выбранные герои имеют HP ≤ 0** — переход в `game_over`.

Пощада учитывается через `spared` либо достижение `spare_progress >= spare_max`.

**`after_fight`** — тот же файл, строка 367:

- подготавливает и начисляет опыт;
- показывает `post_battle_xp_screen`;
- очищает часть боевого интерфейса и выбранных целей;
- снимает связь щита;
- возвращает `game_screen`.

**Победа не обязана ждать конца раунда:** проверка независима от основной последовательности.

## 6. Найденные проблемы в цикле

### 1. Некоторые действия не расходуют ход

После ряда действий герой остаётся с `turn = 1`, то есть доступен повторно:

- первые атаки Криса — `game/1_ПЕРС_АТАКИ_ЛЕЙБЛЫ.rpy:175, 436, 553`;
- `finish_act` — `game/1_ПЕРС_ДЕЙСТВИЯ.rpy:1454`;
- предметы — `game/1_ПЕРС_ИНВЕНТАРЬ_ХОД.rpy:107`.

При этом другие атаки ставят `turn = 0`.

**Следствие:** единое правило «одно действие героя за раунд» сейчас не соблюдается. Такие действия позволяют повторно выбирать героя, задерживая переход к врагам.

`turn_is_done` существует, но явных вызовов этого лейбла в `.rpy` не найдено: завершение хода распределено по отдельным действиям.

### 2. Перед атакой врагам выставляется признак завершённого хода

В `apply_debuffs_at_round_end_enemies()`:

```python
if enemy.prone_debuff != 0:
    enemy.turn = 0
else:
    enemy.turn = 1
```

Файл: `game/1_ДЕБАФЫ_СИСТЕМА.rpy:296–305`.

Но `enemyattack` считает `turn == 1` признаком завершения атаки.

**Следствие:** если все активные враги без `prone`, следующая вражеская фаза может сразу завершиться, не дождавшись атак. Логика оглушения также противоречит этой проверке.

### 3. Не все варианты атак имеют полноценное завершение

В `enemyattack`:

- для боёв `2`, `4`, `5` в соответствующих ветках нет таймера завершения или установки `turn = 1`;
- у Джевила атаки описаны только для `current_round == 0` и `1`;
- в бою `13` активны `dummy2` и Тревор, но таймер завершения выставлен только для `dummy2`.

Это потенциальные точки зависания, особенно после исправления проблемы с флагами врагов.

### 4. На старте перезарядки сразу уменьшаются пять раз

В `fightbegin12` после сброса идут **пять вызовов** `tick_battle_ability_cooldowns()`.

Файл: `game/1_ВРАГ_ДИАЛОГИ.rpy:86–90`.

Фактическая стартовая перезарядка:

```python
max(0, initial_cooldown - 5)
```

То есть она не соответствует комментарию о восстановлении исходных значений.

### 5. Старт боя не делает полный сброс участников

Вызов `reset_active_enemies_for_new_battle()` закомментирован на строке 74. В `fightbegin12` также нет общего восстановления `turn` героев и врагов.

Повторный бой может наследовать состояние предыдущего, если его не подготовил вызывающий код.

---

**Главные места для работы с раундами:**

- **Начало боя:** `game/1_ВРАГ_ДИАЛОГИ.rpy` → `fightbegin12`.
- **Конец фазы героев:** `game/1_ВЫБОР ПЕРСОВ.rpy` → `available_chars == 0`, затем `enemyattacklabel`.
- **Вражеская фаза:** `game/1_АТАКИ_ВРАГОВ.rpy` → `enemyattack`.
- **Конец раунда / начало следующего:** тот же файл → `afterenemyattack`.
- **Окончание боя:** `game/1_ПОСЛЕ БОЯ.rpy` → `check_enemy_status`, затем `after_fight`.
